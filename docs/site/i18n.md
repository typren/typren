Typren's i18n covers two separate concerns: how a locale maps onto a URL, and
how a page's content falls back when a translation is missing. Both are
driven by one `I18nConfig` block.

## Configuring locales

```ts
import { resolveI18n } from "@typren/core/i18n";

const i18n = resolveI18n({
  locales: ["en", "es"],
  defaultLocale: "en",
  routing: "prefix-except-default",
});
```

`resolveI18n` fills in defaults and throws early if `defaultLocale` is not in
`locales`. Omitting the whole block collapses to a single implicit locale, so
a single-locale site behaves exactly as if i18n did not exist.

| Field | Type | Default | Notes |
|---|---|---|---|
| `locales` | `string[]` | `[defaultLocale]` | allowlist of locales the site serves |
| `defaultLocale` | `string` | `"en"` | must be in `locales` |
| `routing` | `"prefix-except-default" \| "prefix-all"` | `"prefix-except-default"` | see below |
| `messages` | `Record<string, Partial<Messages>>` | — | per-UI-locale editor string overrides |

## Routing modes

- `prefix-except-default`: the default locale is unprefixed (`/about`), every
  other locale is prefixed (`/es/about`). Preserves an existing single-locale
  site's URLs and SEO.
- `prefix-all`: every locale is prefixed, including the default
  (`/en/about`, `/es/about`).

`localizedPath(i18n, path, locale)` builds the public path for a locale under
the configured mode; `localizedHref` does the same but leaves external
links, anchors, `mailto:` and `tel:` hrefs untouched.

```ts
import { localizedPath } from "@typren/core/i18n";

localizedPath(i18n, "/about", "es"); // "/es/about"
localizedPath(i18n, "/about", "en"); // "/about" (prefix-except-default)
```

`routeLocale(i18n, pathname)` is the pure decision function behind the edge
proxy: it returns `{ type: "next" }`, `{ type: "redirect", pathname }`, or
`{ type: "rewrite", pathname }`. Under `prefix-except-default` an explicit
`/en/about` canonicalizes (redirects) to `/about`, so the default locale
never serves two URLs for the same page. Under `prefix-all` a bare `/about`
rewrites to `/en/about` server-side without a redirect round trip.

`routeLocale` is pure (no `next/server` import), so a host's own
`proxy.ts` (Next 16's rename of `middleware.ts`) maps its verdict onto a
`NextResponse` directly:

```ts
import { NextResponse, type NextRequest } from "next/server.js";
import { routeLocale } from "@typren/core/i18n";

export function proxy(request: NextRequest) {
  const route = routeLocale(i18n, request.nextUrl.pathname);
  if (route.type === "redirect") return NextResponse.redirect(new URL(route.pathname, request.url));
  if (route.type === "rewrite") return NextResponse.rewrite(new URL(route.pathname, request.url));
  return NextResponse.next();
}
```

`@typren/core/proxy` is a separate, unrelated concern: it only rewrites
`/<adminRoute>/**` to `/editor/**` for the live-renameable admin route, not
locale routing.

## Content fallback

A page's content is stored per locale. `mergeLocalized(base, loc)`, imported
from `@typren/core` (not the `./i18n` subpath — it lives in `localize.ts`,
which touches `PageContent` and so isn't part of the edge-safe i18n module),
combines
the default-locale page with a locale-specific one:

- `meta`: field-level merge — a translation can override just `title` and
  inherit everything else from the base.
- `slices`: whole-array — the translation's slices replace the base's
  entirely, or fall back to the base's when the translation has none.
  Partial, per-slice translation is not supported; translate the whole page.
- `body`: falls back to the base when the translation omits it.

`ContentStore.getPublished(slug, locale)` applies this automatically:

```ts
const page = await store.getPublished("about", "es");
// page.isFallback is true when no Spanish translation exists at all
// (the English page is served as-is)
```

`localeSubdir(locale, defaultLocale)` is the on-disk/on-repo layout rule both
the markdown and GitHub adapters follow: the default locale lives flat at the
content root, every other locale lives under `<locale>/`.

## Creating a translation

```ts
await store.createTranslation("about", "en", "es");
```

Seeds a draft translation of `about` from the English page's current
content, as a starting point for a translator. No-ops if the Spanish
translation (published or draft) already exists.

> **Cost:** every store method that fans out over every slug or locale
> (`listPages`, SEO's `buildSitemap`) is capped at 8 concurrent adapter calls
> (`mapLimit`), so adding locales multiplies per-build adapter reads but
> never multiplies concurrency. See [cost-and-rate-limits](./cost-and-rate-limits.md).
