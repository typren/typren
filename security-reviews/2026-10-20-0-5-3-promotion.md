# Security review: Typren at 151b9f1

## Summary

Several reviewers working from attacker models (content contributor, low-privilege editor, hosted tenant, malicious npm or remote-note publisher, compromised third party) reviewed Typren at commit 151b9f1. The review found no critical or high-severity issues, so the outcome is pass. Four medium findings remain open. The most significant is that the filesystem markdown adapter follows symlinks. If a symlink is planted in the content tree, an editor can read any file the server can read, and an editor with write access can overwrite any writable file. Two reviewers reported this independently, and it appears below as two rows with one root cause. The other two medium findings affect release integrity. The canary workflow can still poison the Actions cache that the release build restores. The release build also runs lint and test code in the same workspace as the final rebuild. Nine low findings cover gaps between the docs and the code, a few hardening points, and one authorization gap in the list endpoints when a read policy is scoped by slug. Four claims were refuted. The two previously fixed medium issues (Notion CR folding and canary job isolation) still hold.

## Refuted claims

- **SliceZone spreads content-authored keys as React props, so `dangerouslySetInnerHTML` can be injected** (`packages/core/src/templates/init.ts`). The only components Typren ships (Hero, Prose) destructure named props and never spread them onto DOM nodes. Registry lookups use `Object.hasOwn`, so overriding `slice` can only select an already-registered component. Exploiting this needs a host-written component that spreads props onto the DOM, and that component would be the defect. What remains is hardening and documentation advice for hosts.
- **The Notion `bodyProperty` body is unescaped rich text** (`packages/core/src/notion-adapter.ts`). The docs promise escaping only for the block-to-markdown conversion. A `bodyProperty` body is round-tripped author markdown, so escaping it on read would corrupt it. It has the same trust level as bodies from every other adapter. Typren never renders a body as HTML.
- **A percent-encoded `/editor` path bypasses `typrenBlocksDirectEditorAccess`** (`packages/core/src/proxy.ts`). This was reproduced against Next 16.4.1. The editor routes are dynamic and are matched against the raw encoded pathname, so `/%65ditor` and case variants return 404 even without the proxy. Dot-segment variants are normalized before the check runs.
- **Bare and slash canonicalization turns a backslash path into an off-site 301** (`packages/core/src/static-host.ts`). Browsers normalize `\` to `/`, and the existing `//` guard catches the result. `%5C` stays encoded and resolves on the same origin. Only a non-browser client can send a raw backslash, and that leaves no victim. At most this is defense-in-depth hardening: refuse `\` at `charAt(1)`.

## Verified clean

**Fixes from earlier reviews**
- The Notion CR handling still holds. `notion-blocks.ts` folds `\r\n?` before splitting in the code case and in the directive parser (lines 125, 163 and 266).
- Canary job isolation still holds. The check jobs in `canary-frameworks.yml` and `canary-providers.yml` have `contents: read`, `persist-credentials: false`, `setup-bun no-cache: true`, and `npm install --ignore-scripts`. Only the separate report job (`needs` + `if: always()`) holds `issues: write`, and it installs nothing. The remaining cache-scope issue is reported as #4.

**Content parsing and rendering**
- safe-matter refuses the javascript engine under every alias. YAML loads with js-yaml 5.4.3, `CORE_SCHEMA` plus timestamp and merge, `maxAliases: 0`, a 256 KB cap and a maximum depth of 100. `__proto__` keys become own properties. `stringifyMatter` uses `noRefs`, a node cap, a cycle check and a re-parse.
- Prototype pollution is guarded in locale delta helpers, forms parsing (null-prototype objects, iteration over the schema), export-api `readDotPath`, the slice registry (`Object.hasOwn`) and collection routes (`Map`).
- JSON-LD escapes `<`. The markdown mirror matches only safe slugs, serves `text/markdown`, and returns published content only. The sitemap and robots output are built from validated slugs.
- In Notion block markdown, prose is escaped for HTML entities and markdown. `safeUrl` allows only http(s) and mailto. Code fences are always longer than any backtick run inside them, and directive names are checked against `SAFE_NAME`.
- Input-facing regexes were reviewed for ReDoS. None is super-linear on attacker input except the S3 XML parser (#10).

**API, auth and tenancy**
- `createTyprenApi` enforces the same-origin check before building config. It refuses Origin `null`, `Sec-Fetch-Site: cross-site` and same-site sibling origins. It emits no CORS headers and does not echo `e.message`.
- Every write route goes through a `makeActions` guard that carries slug, locale, collectionId, siteId and accountId. Rename and duplicate also authorize the destination slug.
- Settings draft, publish and bootstrap writes require the separate `admin` action. The bootstrap patch is checked against a key allowlist and the merged result is validated.
- Per-record reads call `authorize('read')`. Draft, settings and media responses are `private, no-store`.
- localAuth fails closed in production, off loopback, on a non-loopback Host header, or when forwarding headers are present.
- The OIDC, next-auth, Clerk, better-auth and Supabase mappings require an allowlist and a verified email. Admin requires `adminRoles`. OIDC accepts only asymmetric algorithms, requires an https `jwks_uri` and checks the issuer. Clerk roles are bound to the organization. `filePolicy` denies by default.
- The hosted tier rebuilds config per request and caches nothing across tenants. `createSettingsStore` refuses a missing or overlapping settings adapter. S3 media is scoped to its prefix.

**Paths, files and media**
- Path joins: the markdown and GitHub adapters enforce `SAFE_SLUG` plus a locale allowlist. GitHub `isAllowedRepoPath` blocks `..`, dotfiles and manifests, and refuses symlink entries. fs-media uses `SAFE_NAME` plus a `..` check, and S3 uses `SAFE_ID` plus a prefix check. Locale writes go through `joinInside`.
- Media: `processUpload` sniffs bytes and re-encodes raster images. It sanitizes SVG with DOMPurify, forbids style and image, and drops external `href` and `url()` values. The known LOW for `image-set()` is unchanged. Uploads re-check same-origin and authorization and enforce `Content-Length` before buffering.
- CLI `init` checks existence with lstat and refuses symlinks on the path before any write.

**Redirects and edge hosting**
- Redirect map entries and edge targets refuse `//`, backslashes and control characters. Canonicalization never emits a `//` Location. The Worker rewrites `pathname` rather than resolving a URL. The canonical host is validated, and passthrough segments in the CloudFront function are regex-validated and JSON-stringified.

**Integrations**
- The GitHub webhook requires a secret and computes the HMAC over the raw body with a constant-time compare. The body is capped at 5 MB. A delivery is marked as seen only after `onChange` succeeds.
- Forms: the body is capped while streaming, the spam verifier fails closed, and responses do not leak sink details. Webhook sinks use `redirect: manual` and 10 s timeouts. HubSpot `hutk` is read only from the cookie. Google Sheets uses `valueInputOption=RAW`. HubSpot and Sheets tokens require `requireEnvRef`.
- Locale export-api enforces the bundle-origin allowlist, sends no auth header to bundle URLs, refuses redirects, and caps downloads and zip inflation. OTA catalogs are hash-verified against the manifest and pass through the HTML allowlist before they are applied.
- `migrate --remote` uses a hardcoded origin, `redirect: 'error'`, a 1 MB cap and a 10 s timeout, and never compiles remote regexes.
- Telemetry does nothing unless `TYPREN_TELEMETRY_URL` is set, honors CI and `DO_NOT_TRACK`, sends only anonymous fields, and is never imported by core.

**CI, supply chain and CLI**
- Every `${{ }}` interpolation in a `run:` block is a value an attacker cannot control. The `pull_request_target` workflows never check out PR code. Actions are pinned to a SHA. ci.yml and the security gate run with `contents: read`, and the gate script runs from the base branch.
- The publish job is the only job with `id-token`. It installs only an exact-pinned npm, runs with `NPM_CONFIG_IGNORE_SCRIPTS`, refuses symlinks when extracting the artifact, and runs publish scripts through `execFileSync` without a shell.
- Every package in bun.lock resolves from the npm registry with sha512 integrity, and `.npmrc` pins the public registry. Published tarballs are limited by the `files` field.
- Git calls in the CLI use `--end-of-options` and strip `GIT_*` variables, and `--base` refs that start with `-` are refused. Wrangler and aws are invoked as argv arrays (`npx --no-install`), and temp files go in `mkdtemp` directories.
