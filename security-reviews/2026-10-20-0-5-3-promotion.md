# Security review: Typren at a635567

## Summary

Several independent reviewers checked commit a635567, and a verifier pass re-checked their claims. No critical or high findings were confirmed, so the release gate passes. Eleven findings remain open: two medium and nine low.

- **First medium:** a Notion code block nested inside a list item can escape its container through a bare carriage return, letting raw HTML or arbitrary block markdown into the rendered page.
- **Second medium:** the framework canary workflow runs unpinned, unlocked npm install scripts on the default-branch cache scope. Through a poisoned setup-bun binary cache, this could plausibly reach the release build.
- **Lows:** five separate reports cover one theme, a write-scoped `GITHUB_TOKEN` exposed to untrusted install code in `canary-frameworks.yml`. The other lows cover:
  - `image-set()` URLs surviving the SVG sanitizer
  - crashes on null slice entries
  - CR/C1 control characters in `migrate --remote` output
  - the export-api size and time caps not covering synchronous create/poll responses

Three claims were refuted. The fixes from the previous review hold.

## Refuted claims

- **CloudFront bare-URL 301 open redirect through a backslash** (`packages/adapter-cloudfront/src/redirects.function.js`)
  - Browsers apply the WHATWG URL parser, which turns `\` into `/` before sending. The existing `charAt(1) !== "/"` guard then catches `//evil...`.
  - A `%5C` form resolves same-origin.
  - Only the attacker's own raw client can send a literal `\`, so no victim is redirected.
  - Hardening only: reject `\` before the canonicalization redirect.
- **`typren init` scaffolds same-origin media that the checklist forbids** (`packages/core/src/templates/init.ts`)
  - The scaffold never sets `allowSvg`, and its `localAuth()` fails closed in production.
  - Raster uploads are re-encoded to WebP/AVIF.
  - The SVG rejection message points to `media-storage.md`, which documents the separate-origin and sandbox-header requirement.
  - Hardening and docs only: refuse `allowSvg` with a relative fs `publicPath`. Checklist line 82 names `publicBaseUrl` where the fs adapter takes `publicPath`.
- **localAuth accepts any `*.localhost` Host, which reopens DNS rebinding** (`packages/core/src/auth/local.ts`)
  - Chrome, Firefox and Edge hard-wire `*.localhost` to loopback, and so do macOS (mDNSResponder, verified) and systemd-resolved, so the attacker's resolver is never asked.
  - The behavior matches `auth-model.md`.
  - One reviewer rated it plausible for Safari, but local verification showed macOS resolves `.localhost` itself.
  - Optional hardening: make `*.localhost` opt-in through an `allowedHosts` option.

## Verified clean

- **Front matter:**
  - The `js` / `javascript` engines (including aliases) are routed to a refusing engine.
  - YAML loads with CORE_SCHEMA plus timestamp and merge, and `maxAliases: 0` is enforced by js-yaml 5.4.3 (verified).
  - Front matter is capped at 256 KB. The dump path bounds nodes and rejects cycles, and stringify re-parses its own output.
  - `__proto__` keys, direct or through `<<` merge, become own properties without touching `Object.prototype`.
  - Docs nit: `security-model.md` calls the option `maxAliasCount`.
- **SVG sanitizer:**
  - Counting `url(` openers fails closed on an unterminated `url(` and on mixed fragment and external values.
  - Backslash escapes are rejected.
  - Non-fragment `href` / `xlink:href` are dropped, `animate` / `set` targeting `href` are removed, and `mpath` href is dropped.
  - `style`, `<style>` and `<image>` are forbidden on top of the DOMPurify svg and svgFilters profiles.
- **markdown-render:** degrades safely on non-array and non-object slice props. Overrides are looked up with `Object.hasOwn`.
- **Write authorization:**
  - Guards carry the target slug, locale, collectionId, siteId and accountId.
  - `renamePage` authorizes both ends. `duplicatePage` authorizes the derived slug before any write. `createTranslation` / `deleteTranslation` carry the target locale.
  - The Notion `draftsWriteThrough` setting gates `saveDraft` and `createTranslation` as `publish`.
- **HTTP API (`api/routes.ts`):**
  - Every write goes through the action or settings-store guards. Reads call `requireRead` before any existence probe.
  - `sameOrigin` runs first on unsafe methods. It refuses cross-site Sec-Fetch-Site, an Origin of `null`, and mismatched hosts. The API emits no CORS headers.
  - Drafts, settings, media and list reads are `private, no-store`.
  - Errors are generic.
  - Bootstrap PUT requires `admin`, rejects unknown keys, and validates the merged result, including `onboarded`.
  - Upload re-authorizes as `uploadMedia`, sniffs the format, and leaves SVG off by default.
- **Path traversal:**
  - The markdown and GitHub adapters check `SAFE_SLUG` and a locale allowlist, and `SAFE_LOCALE` also validates the allowlist entries.
  - GitHub adds `isAllowedRepoPath`.
  - The fs media adapter uses `SAFE_NAME` plus a `..` check. The S3 adapter requires a trailing-slash prefix and only deletes inside it.
  - The Notion page-id path verifies the parent `database_id`.
  - `typren init` refuses symlinked targets.
- **Prototype pollution:**
  - The locale delta and catalog code skips unsafe keys.
  - Forms use null-prototype bodies.
  - The registries use `Object.hasOwn`.
  - `readDotPath` refuses unsafe segments, and `filePolicy` lookups fail closed.
- **Output encoding:**
  - JSON-LD escapes `<`.
  - Sitemap and redirect URLs are built only from safe slugs.
  - Redirects are exact-key lookups that refuse protocol-relative, backslash and control-character targets.
  - Notion prose escaping covers entities, markdown metacharacters, setext lines, a URL scheme allowlist, and CR folding in inline code.
  - Scaffolded components render through JSX, and React 19 neutralizes `javascript:` hrefs.
- **Locale export-api (bundle path):**
  - Redirects are manual, and 3xx responses are refused.
  - Bundles are capped at 50 MB as a running count, with a 60 s timeout.
  - Zip entry and size caps are re-checked on the inflated bytes.
  - Logged URLs drop the query string.
  - Skipped locale names are escaped with `JSON.stringify`, and path-like names throw.
  - The origin allowlist is https-only and dot-anchored, and path prefixes must end in `/`. The Lokalise virtual-hosted bucket is admitted without loosening the matcher.
  - The locale OTA HTML gate is allowlist-based and fails closed without a DOM.
- **Editor preview:**
  - The iframe is sandboxed without `allow-same-origin`.
  - Messages are accepted only when `event.source` is the iframe's `contentWindow`, and only existing string fields can be edited.
  - The in-frame bridge pins one origin.
- **localAuth:**
  - Refused in production unless explicitly opted in.
  - Requires a `127.0.0.1` bind and a loopback Host.
  - Refuses `Forwarded`, `X-Real-IP`, and non-loopback `X-Forwarded-For` or `X-Forwarded-Host` values.
  - Fails closed on throw. The Host-rewriting proxy limit is documented.
- **Auth adapters (oidc, next-auth, clerk, better-auth, supabase):**
  - All require an allowlist and fail closed. Only IdP-verified emails can match.
  - `admin` requires `adminRoles`.
  - OIDC allows only asymmetric algorithms and requires the core claims.
  - Clerk roles are bound to `organizationId`. Supabase roles come only from `app_metadata`.
  - `filePolicy` denies by default.
- **Webhooks and forms:**
  - The GitHub webhook does a constant-time HMAC check over the capped raw body before parsing, with delivery dedupe.
  - Forms cap the body, use null-prototype records, and offer an opt-in CORS allowlist.
  - Sink credentials must be environment references. Spam checks fail closed.
  - Sinks use manual redirects and timeouts, and no sink detail reaches the public response.
- **Tenancy:** config is rebuilt per request from a factory. `siteId` without `settingsAdapter` throws.
- **`migrate --remote` (apart from finding #10):**
  - The origin is hardcoded, with `redirect: 'error'` and a 1 MB streamed cap.
  - Package and semver validation is anchored.
  - Remote regexes are never compiled.
- **review command:**
  - Base refs starting with `-` are rejected, and `--end-of-options` is used at every git call.
  - The PR body fence is longer than any backtick run.
- **Canary scripts:**
  - `report.mjs` and `next-local-auth.mjs` use `execFileSync` with argv arrays.
  - `run:` interpolation uses only static matrix values and step outcomes.
  - Triggers are schedule and dispatch only. Top-level permissions are `contents: read`.
  - Issue lookup requires the `canary` label.
  - `lokalise-signals.mjs` sends the token only to api.github.com and runs only lockfile-pinned code.
  - `next dev` binds to `127.0.0.1` in a private temp dir.
  - The scripts are not part of any published package.
- **Release and CI:**
  - `release.yml` is unchanged. `id-token: write` exists only on the publish job, inside the release environment, with ignore-scripts on.
  - The artifact copy refuses symlinks. Actions are SHA-pinned.
  - `ci.yml` and the security-review gate use plain `pull_request` with `contents: read`, and the gate runs from the base branch.
  - The `pull_request_target` jobs never check out PR code.
  - No setup-node auto-caching and no `actions/cache` use.
  - The pre-push gate is intact.
  - The eslint and vitest config changes have no security effect.
- **Attack chains that did not compose:**
  - anonymous visitor to write
  - editor to admin through settings
  - editor to the policy file
  - content PR to code execution beyond what a PR already is
  - tenant to tenant
  - compromised TMS, Notion, HubSpot or webhook receiver to the site
- **Carried over:** previously accepted open lows remain open and are not re-reported here: the gate denylist, the floating setup-bun tag in version-pr, front-matter aliases claiming reserved paths, and the read-side `isUnauthorized` regex.
